💡 What's happening here?
Without HoneyShield: An attacker can try unlimited passwords. The server processes every request and the attacker eventually finds the right password through trial and error — this is a classic brute force attack.

With HoneyShield: After 3 failed attempts, the system detects the brute force pattern, blocks the IP, logs the event to the database, and redirects the attacker to a decoy honeypot server — wasting their time while collecting threat intelligence.

💡 What's happening here?
The Honeypot Trap: HoneyShield injects a hidden form field into the login page that is invisible to real users (hidden via CSS). Bots and automated scripts auto-fill every field they find — including hidden ones.

Detection logic: If the hidden field is filled → it's a bot → block immediately and log the event. Real users never see or fill this field, so they are never affected. This catches bots with zero false positives.
